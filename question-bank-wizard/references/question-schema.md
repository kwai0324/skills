# 任务数据与题型字段

每门课程、每个培养层次使用独立的 bank.json。该文件是本技能的任务容器，程序导出器直接接收其中每卷的题型字典，不把整个容器当作题目数组。

## 任务容器

下例展示可先运行 plan 的方案。papers中的数组在生成时填充，空数组不能通过最终check。

```json
{
  "course_name": "计算机应用基础",
  "education_level": "专科",
  "chapters": ["计算机基础知识", "办公软件应用"],
  "counts": {"single": 4, "multiple": 13, "judge": 2},
  "paper_labels": ["单卷"],
  "papers": {"单卷": {"single": [], "multiple": [], "judge": []}},
  "notes": "范围由用户指定。尚未提供历史题库。"
}
```

course_name为原课程名，不用最终文件名替换。education_level只能为中专、专科、本科或空字符串；空字符串表示用户明确选择不指定。

chapters为非空且互异的章节名称数组。counts以程序题型键记录每卷新增数量，均为非负整数，至少有1种题型大于0。标准模式固定为single等于150、multiple等于90、judge等于60。

paper_labels只能为单卷标签数组，或按A、B排列的2个标签。A、B模式的实际写法如下。

```json
{"paper_labels": ["A", "B"], "papers": {"A": {}, "B": {}}}
```

papers中的每卷都分别生成counts要求的全部题型数量。notes用于记录教材依据、目标语言、额外难度、历史范围及进度。外语课程无法从名称明确识别时，额外使用language字段记录用户确认的语种，例如英语或日语。

## 通用题目字段

q为题干，ans为答案，exp为解析。文本字段使用非空字符串。每道顶层题目都添加ch，表示chapters中的章节下标，从0开始；可以同时保存ch_name，但必须与对应章节名称相同。

章节号仅用于元数据，不写入题干。复合题的ch写在材料父项，子题无需重复。不要把显示题号、题型标签、章节规划或来源笔记拼进q。

## 11种题型

single对应单选题。必填字段为q、A、B、C、D、ans、exp、ch。恰好4个选项，ans为A至D中的1个大写字母。解析逐项说明选项真伪和依据。

multiple对应多选题。必填字段为q、A、B、C、D、E、ans、exp、ch。恰好5个选项，ans为允许的13种升序组合之一。解析完整说明5个选项，不漏选正确项。

judge对应判断题。必填字段为q、ans、exp、ch。q为完整明确的陈述句，避免可能、有时、一般、通常、大多数等模糊词。不通过微小措辞陷阱制造错误，错误题解析包含正确说法。

glossary对应名词解释。必填字段为q、ans、ch。q为核心术语，ans包含本质特征、适用范围和必要要素。

short对应简答题。必填字段为q、ans、ch。设问明确、答案边界清晰，ans含3至5个准确要点。

essay对应论述题。必填字段为q、ans、ch。要求综合分析和论证，答案详细、论据充分、逻辑清楚。

case对应案例分析题。父项必填case、questions、ch。case为可信且贴合章节的材料，每份材料包含2至3个子题；子题必填q、ans。题量按材料份数计算，不把子题数量当成顶层题量。

comprehensive对应综合分析题。必填字段为q、ans、exp、ch。q含自足材料与综合任务，ans先给结论再分点写依据、分析和措施，exp包含解题思路与评分要点。

translate对应翻译题。必填字段为q、ans、ch。q为专业相关的中文原文，ans为课程目标语种译文。术语使用公认译法。

reading对应阅读理解。父项必填passage、questions、ch。每篇固定5个单选子题，子题必填q、A、B、C、D、ans、exp。覆盖细节、推断、主旨、语境词义、逻辑理解。英语材料每篇200至300个英文单词。题量按篇数计算，2篇等于10道子题。非英语篇幅先确认。

cloze对应选词填空。必填字段为q、A、B、C、D、ans、exp、ch。每题为含1个空的独立句子，以连续4个下划线标空，4个选项为相近词或相同词性，恰好1个正确答案，考查词汇、语法或搭配。

用户说填空题或完形填空时，不能直接当作cloze。先确认是程序现有的独立句子选词填空，还是其他题型。阅读子题与cloze仍须正确选项唯一、解析逐项准确；程序没有要求它们另行套用整卷single的答案配额。

## 数据约束与排除文件

题目内容为纯文本，JSON字段名和机器语法保持原样，不能把英文引号和逗号替换为中文符号。JSON文件使用UTF－8编码，保存原始完整答案与解析，不用Markdown围栏包装文件内容。

历史排除文件支持完整的本技能bank.json，或包含题干、案例、阅读材料对象的JSON数组。最简数组示例如下。

```json
[
  {"q": "某道需要排除的完整旧题干"},
  {"case": "需要排除的完整案例材料"},
  {"passage": "需要排除的完整阅读材料"}
]
```

用户提供旧Word或Excel时，先只提取去重所需的题干与材料，另存排除JSON并记录源文件。仅有历史题干不能声称拥有可合并的完整答案。不要自动读取配置文件、登录信息或数据库凭据。

check脚本会跨题型、跨卷检查顶层题干与复合材料重复，复合题内部也检查重复子题；不同阅读材料之间允许使用相同的常见设问形式。内容相似但字符串差异较大的题目仍需语义复核。
